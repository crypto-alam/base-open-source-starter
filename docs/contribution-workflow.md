# Contribution Workflow

## Overview

This project welcomes clear, focused, and useful contributions.

## Before Making Changes

Before contributing, review the existing documentation and source code
to understand the structure of the project.

## Making a Contribution

A simple contribution workflow is:

1. Identify an improvement or documentation task.
2. Make the required changes.
3. Review the changes carefully.
4. Test code changes when applicable.
5. Write a clear commit message.
6. Submit the contribution for review.

## Commit Messages

Commit messages should briefly describe what was changed.

Examples:

- `docs: improve installation guide`
- `docs: add development notes`
- `fix: correct contract example`

## Documentation Contributions

Documentation should be clear, concise, and easy for new developers
to understand.

## Security

Never commit private keys, seed phrases, passwords, API credentials,
or other sensitive information to the repository.

## Goal

The contribution workflow is intended to make the project easier to
maintain and easier for new contributors to understand.
